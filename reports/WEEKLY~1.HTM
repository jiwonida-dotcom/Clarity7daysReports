DEV-01P1 이벤트·제휴 랜딩 페이지에서 스크립트가 중단됨
증상 페이지 스크립트가 실행 도중 멈춥니다. 없는 요소를 찾은 뒤 그 자식(.children)에 접근하면서 발생합니다. Cannot read properties of undefined (reading 'children') ← Chrome·Edge·Samsung undefined is not an object (evaluating 'e.children') ← Safari 메시지는 둘로 나뉘지만 원인은 같은 코드 한 곳입니다.
영향 최근 주 47,760세션(전체의 14.2%). 4주간 10.6% → 11.1% → 11.3% → 14.2%로 계속 늘고 있습니다. 같은 기간 다른 오류는 오히려 줄었기 때문에, 전체 오류 증가는 사실상 이 건 하나 때문입니다.
발생 위치
  • /event-benefit/event/ongoing/12503 — 해당 페이지 세션의 66.4%
  • /event-benefit/event/ongoing/12624 — 64.6%
  • /event-benefit/event/ongoing/10314 — 61.5%
  • /product/tmoneykpassbp — 50.6%
개통 퍼널·요금 납부 페이지에서는 발생하지 않습니다.
브라우저 Samsung Internet 55.9% · PC Chrome 32.9% · Edge 29.1% · Chrome Mobile 11.4% · Mobile Safari 0.0%(117,508세션 중 2건). → Chromium 계열에 집중되어 있어 Safari로만 테스트하면 재현되지 않습니다.
재현 Samsung Internet(또는 PC Chrome)으로 /event-benefit/event/ongoing/12503 접속 → 개발자도구 콘솔 확인. 발생률이 66%라 대부분 한 번에 재현됩니다.
조치 ① .children 접근 전 요소 존재 여부 확인(null 가드) 추가
② 스크립트 실행 시점을 요소 렌더 이후(DOMContentLoaded)로 이동
③ 공통 스크립트가 페이지마다 없는 선택자를 무조건 참조하지 않도록 분기
확인 지표: 수정 후 Clarity JS 오류 세션 비율이 23.1% → 9%대로 내려가면 정상
DEV-02P1 요금 납부에서 다음 단계로 못 넘어가는 비율 급증
증상 납부 정보 화면(/bill/pay/info)까지 온 사용자가 결제 진행 화면(/bill/pay/payment)으로 넘어가지 못하는 비율이 크게 늘었습니다.
영향 통과율 83.8% → 84.2% → 74.7% → 61.1% (4주 추이). 최근 주 진입 38,297세션 중 14,898세션이 결제 화면에 도달하지 못했습니다. 개통 퍼널보다 트래픽이 3배 이상 커서 실제 손실 규모는 이쪽이 가장 큽니다.
발생 시점 7/28 ~ 8/03 주차부터 꺾이기 시작해 다음 주에 더 떨어졌습니다. 그 이전 2주는 83~84%로 안정적이었습니다.
확인 요청
  • 7/28 ~ 8/03 기간 배포 이력 — 결제 관련 변경 있었는지
  • PG·결제 모듈 연동 변경 또는 버전 업 여부
  • 본인확인·약관 동의 등 중간 단계가 추가되었는지 (기획 변경이면 정상 수치)
조치 기획 의도된 변경이면 종료, 아니면 회귀로 처리. 먼저 배포 이력 대조 → 변경 없으면 해당 구간 세션 리코딩 확인 순서를 권장합니다.
DEV-03P2 마이페이지 데이터 잔여량 게이지가 동작하지 않음
증상 /my/main의 데이터 사용량 프로그레스 애니메이션 호출이 실패합니다. uiCommon.progressAni.amountBar is not a function 10,440 세션 Identifier '$commUtil' has already been declared 2,994 세션
원인 추정 ① uiCommon 로드가 끝나기 전에 amountBar()를 호출 — 스크립트 순서 문제
② $commUtil 중복 선언 = 공통 스크립트가 두 번 삽입되고 있음
영향 /my/main은 전체 세션의 34.4%가 진입하는 첫 화면이고, dead click(눌러도 반응 없는 클릭)이 12,966회로 사이트 1위입니다. 게이지 미동작이 여기에 영향을 줬을 가능성이 있습니다.
조치 공통 스크립트 중복 삽입 제거 → 로드 순서 정리 → 호출부에 방어 코드 추가
DEV-04P2 개통 첫 화면에서 눌러도 반응 없는 클릭이 많음
증상 /onsale/usimInfoWrite에서 dead click 6,489회 발생 — 진입 세션당 0.61회입니다. 즉 두 세션 중 한 번꼴로 "눌렀는데 아무 일도 일어나지 않는" 클릭이 나옵니다. 같은 화면에서 rage click(같은 자리 연타)도 570회로 사이트 4위입니다.
확인 방법 Clarity 히트맵에서 해당 페이지를 열면 클릭이 몰린 지점을 볼 수 있습니다. 두 경우를 구분해 주세요.
  • 클릭 가능해 보이지만 실제로는 버튼이 아닌 요소 (안내 텍스트·아이콘 등)
  • 버튼이 맞는데 이벤트 바인딩이 빠졌거나 비활성 상태인 요소
조치 전자면 시각 처리 변경(클릭 가능해 보이지 않게), 후자면 바인딩 수정. 확인 지표: 세션당 dead click 0.61회 → 0.3회 이하
DEV-05P3 페이지 로딩 속도 — 모바일 권장치의 2~3배
현황 모바일 평균 로드 7.02초 / LCP 4.67초 (Google 권장 2.5초 이하)
PC는 로드 3.60초로 가장 빠른데 LCP만 17.13초로 역전 — 계측 오류이거나 지연 로딩되는 대형 요소(배너·차트)가 있을 수 있습니다.
조치 ① PC의 LCP 대상 요소부터 특정 (계측 오류면 제외 처리)
② 실제 지연이면 히어로 이미지·배너 우선순위 조정, 지연 로딩 대상에서 제외
DEV-06P3 유입 경로 계측 누락 (GTM 작업)
현황 전체 세션의 92%에 캠페인 파라미터(UTM)가 없습니다. 이 때문에 Direct 채널이 78%로 부풀려져, 어떤 유입이 성과를 냈는지 판단할 수 없습니다.
추가 건 모바일 App/Web 구분용 커스텀 태그 platform도 현재 데이터가 반환되지 않습니다. UA에 'umobileapp' 포함 → clarity("set","platform","app") 그 외 → clarity("set","platform","web") GTM의 MS_Clarity 태그에서 위 설정이 정상 동작하는지 함께 확인 부탁드립니다.
조치 앱 인입·QR·오프라인 유입 링크에 UTM 부여 → GTM 태그 발화 조건 점검 → platform 태그 정상화

## 이번 4주 핵심 결론

### 1. 전체 트래픽은 안정, 문제는 구성에 있다

세션은 336K → 354K → 348K → 337K로 **±5% 박스권**입니다. 추세적 감소가 아니므로 총량보다 아래 구성 변화를 봐야 합니다.

### 2. 4주 연속 단조 악화 지표 2종

| 지표 | W1 | W2 | W3 | W4 |
|---|---|---|---|---|
| JS 오류 세션 비율 | 20.2% | 20.5% | 21.7% | **23.1%** |
| Quick back 세션 비율 | 28.1% | 28.1% | 29.5% | **30.2%** |

트래픽은 등락했는데 이 둘만 한 방향으로 움직였습니다. 유입 변동으로 설명되지 않는 **코드 측 회귀**로 봅니다.

### 3. 요금 납부 전환율 붕괴 — 절대 손실 최대

`/bill/pay/info` → `/bill/pay/payment` 통과율이 **83.8% → 84.2% → 74.7% → 61.1%**로 2주 만에 23.1%p 떨어졌습니다.
최근 주 진입 38,297세션 중 **14,898세션**이 결제 화면에 도달하지 못했습니다. 개통 퍼널보다 트래픽이 3배 이상 커서 실제 손실은 이쪽이 가장 큽니다. **7/28~8/03 주차가 변곡점**입니다.

### 4. JS 오류 증가는 단일 버그 하나가 만든 것

총 JS 오류를 `children` 오류와 나머지로 분해하면 원인이 분명해집니다.

| 주차 | JS 오류 | children | 기타 | children 비중 |
|---|---|---|---|---|
| W1 | 67,888 | 35,712 | 32,176 | 52.6% |
| W2 | 72,690 | 39,491 | 33,199 | 54.3% |
| W3 | 75,536 | 39,325 | 36,211 | 52.1% |
| W4 | 77,932 | 47,760 | **30,172** | **61.3%** |

4주간 JS 오류는 +10,044건 늘었는데 `children`만 +12,048건 늘고 **기타 오류는 –2,004건 줄었습니다**.
특히 W3→W4는 기타가 –6,039건 급감했는데도 총량이 늘었습니다. 즉 **나머지 오류는 개선됐고, 이 버그 하나가 그 개선을 덮었습니다**.

### 5. 개통 전환율 상승은 일부 착시

W4 전환율 25.4%는 4주 최고지만, 같은 주 PC 비중이 9.9%로 최고였습니다. PC 완료율이 모바일의 1.42배라 **디바이스 믹스 효과가 섞여** 있습니다. 전환 성과는 디바이스별로 나눠 봐야 합니다.

### 6. 모바일 개통 완료율은 4주 내내 PC보다 낮다

| | W1 | W2 | W3 | W4 |
|---|---|---|---|---|
| 모바일 | 15.3% | 17.3% | 14.3% | 21.2% |
| PC | 21.1% | 28.1% | 18.4% | 30.1% |
| 격차 | 1.38배 | 1.62배 | 1.29배 | 1.42배 |

트래픽의 89%가 모바일이므로 손실 규모는 모바일이 압도적입니다. PC 수준까지 올리면 최근 주 기준 **+1,049건**입니다.

## 데이터 정의와 한계

리포트를 읽기 전에 알아야 할 제약입니다.

**퍼널 수치는 순차 전환이 아닙니다.** Clarity 자연어 분석 도구는 페이지별 독립 세션 수만 반환하므로, 리포트의 퍼널은 **페이지 방문 기준 근사치**입니다. 정밀한 순차 전환율은 Clarity 퍼널 대시보드에서 확인해야 합니다. 3단계(`/onsale/identification`)가 2단계보다 큰 것도 이 때문입니다 — `contains` 매칭이고 별도 진입 경로가 있습니다.

**디바이스별 퍼널은 페이지뷰 기반입니다.** `openRequestComplete` 기준이며 세션 기준 수치와 분모가 다릅니다. 절대값보다 **PC/모바일 격차 비율**을 보는 용도입니다.

**주차별 합산 쿼리는 개별 조회와 0.5% 내외 차이가 납니다.** 4주 비교의 일관성을 위해 합산 쿼리 값으로 통일했습니다.

**퍼널 도메인은 `online.uplusumobile.com`입니다** (`www` 아님). `/onsale/partner/...` 변형은 제휴 채널이라 별도 세그먼트로 집계했습니다.

**모바일 App/Web 분리는 불가합니다.** 커스텀 태그 `platform`(app/web) 데이터가 반환되지 않아 Mobile로 합산했습니다 → DEV-06.

**상관관계는 인과가 아닙니다.** DEV-01의 페이지 단위 동시 발생은 강한 정황이지만 인과를 증명하지 않습니다. 퍼널 진입 이후 완료율은 오류 유무와 사실상 같습니다(17.96% vs 18.28%) — **전환 손실은 현재 데이터로 입증되지 않았습니다**.

## 개통·가입 퍼널 정의

셀프개통 기준 6단계이며, 4·5단계는 셀프/상담 경로를 OR 합산합니다.

| 단계 | 이름 | 경로 |
|---|---|---|
| 1 | 상품 정보 입력 | `/onsale/usimInfoWrite` |
| 2 | 가입 유형 선택 | `/onsale/subscriptionType` |
| 3 | 가입자 정보 입력 | `/onsale/identification` (contains) |
| 4 | 가입번호/정보 입력 | `/onsale/carrierInfo` **또는** `/onsale/callPhoneAuth` |
| 5 | 납부 정보 / 상담일정 | `/onsale/paymentCredit` **또는** `/onsale/callConsultingDate` |
| 6 | 가입 정보 확인 | `/onsale/confirmJoin` |
| 완료 | 개통·가입 완료 | `/onsale/openRequestComplete` + `/onsale/onlineApplicationComplete` |

4·5단계에서 앞쪽(`carrierInfo`/`paymentCredit`)은 셀프개통, 뒤쪽(`callPhoneAuth`/`callConsultingDate`)은 상담사개통 경로입니다.

## 리포트 갱신

리포트는 Claude 스킬 `clarity-daily-report`로 생성합니다. 갱신 시 다음 순서를 따릅니다.

1. 대상 기간 확정 — 실행일을 제외한 **최근 완결 7일**(어제부터 거슬러 7일)
2. Microsoft Clarity 커넥터로 지표 수집 — 세션·디바이스·퍼널·마찰 신호·JS 오류·채널
3. 직전 7일 대비(WoW) 계산 — **±15% 이상 변동은 경고 플래그**
4. 마찰 세션 리코딩 3~5건 선별 — 퍼널 이탈·dead click 다발 위주
5. 리포트 렌더링 후 `reports/`에 날짜 파일명으로 추가, 최신본을 `index.html`로 갱신

새 주차가 쌓이면 메인 리포트의 `W` / `D` 배열에 주차를 추가하면 자동으로 선택 항목과 스파크라인에 반영됩니다.
